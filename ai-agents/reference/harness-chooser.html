1. Workflow or agent? Decide per step

If the step…Build it asPattern
has a known number of steps (one query, one classification)workflow step: one call, validated output, your code continuesprompt chaining, routing
needs an unknown number of steps, each depending on the lastagent loop with a stopping condition (round, token or query budget)agent
splits into independent partsparallel calls, merged by codeparallelization, orchestrator-workers

"Workflows offer predictability and consistency for well-defined tasks, whereas agents are the better option when flexibility and model-driven decision-making are needed at scale." Building effective agents

2. What a harness owns

JobMinimum
Stop reasonstool_use → run tools · end_turn → answer · max_tokens → raise, never return · refusal → safe message or fallback
Tool errorsException → tool_result with is_error: true, same tool_use_id
LimitsBounded loop + one final call with tool_choice: {"type": "none"}, tools still declared
Conversation stateKnow where history lives (your memory/DB, or the provider's servers)
ContextCache breakpoints (tools → system → messages), compaction, append-only history (thinking blocks back unchanged)
Output contractStructured outputs / strict tools, not "Return ONLY valid JSON"
Model & API churnTrack removed params (e.g. temperature → 400 from API version 2026-10-21; forced tool_choice 400 on Opus 5.5 / Sonnet 5.5)
Usage & tracesRecord usage per call, incl. cache reads/writes

4. Snippets (anthropic 2.x, Python)

Workflow step with a guaranteed schema

class Query(BaseModel):                         # Pydantic model = the output contract
    dimension: Literal["Region", "Category"]    # Literal → JSON Schema enum
    descending: bool                            # every field required by default

r = client.messages.parse(                      # sends output_config.format = Query's schema
    model="claude-opus-5-5", max_tokens=16000,  # thinking counts toward max_tokens
    messages=[{"role": "user", "content": q}],  # no "Return ONLY JSON" needed
    output_format=Query,                        # constrained decoding to this schema
)
query = r.parsed_output                         # a validated Query instance

Strict tool (schema-valid arguments)

{"name": "get_field_values",                     # tool name the model calls
 "strict": True,                                 # top-level on the tool, not on tool_choice
 "input_schema": {"type": "object",              # arguments are one JSON object
   "properties": {"fields": {"type": "array", "items": {"type": "string"}}},  # list of captions
   "required": ["fields"],                       # strict needs required…
   "additionalProperties": False}}               # …and additionalProperties: false

Tool Runner

@beta_tool                                       # schema from type hints + docstring
def query_datasource(dimension: Dim) -> str: ... # exceptions → is_error results

runner = client.beta.messages.tool_runner(       # SDK runs the loop
    model="claude-opus-5-5", max_tokens=16000,   # same request fields as messages.create
    max_iterations=5,                            # stopping condition; no forced final answer
    thread=False,                                # 2.x default is a server-side message thread
    tools=[query_datasource], messages=msgs)     # decorated functions, not dicts
final = runner.until_done()                      # last assistant message (check its stop_reason)
