The five boxes (course terms)

TermMeaningFrom
① ModelThe LLM that reasons: Claude, Gemini, an open-weight model.L1
② Model accessWho serves the model to you, under which contract, credentials and region: the Anthropic API, Bedrock, Google Cloud, or a server you run. Decides where prompts and tool results go.L1
③ HarnessThe code that runs the agent loop, keeps the conversation and handles errors. Your own loop, or an SDK/framework that provides one.L1
④ Context & toolsEverything the model sees (system prompt, org prompt, metadata, docs, history) and everything it can ask to do (tools).L1
⑤ HostingWhere your code (③ + ④) runs: Render, Cloud Run, Agent Runtime, a VM, the customer's Kubernetes. Separate from where the model runs.L1
Org promptLavi's term: customer-specific standing instructions (business vocabulary, rules) added to the system prompt.L1

Agents and the loop

TermMeaningFrom
Workflow"Systems where LLMs and tools are orchestrated through predefined code paths." Your code decides the steps.Anthropic · L1
Agent"Systems where LLMs dynamically direct their own processes and tool usage." The model decides the next step.Anthropic · L1
Agent loopCall the model; while stop_reason is tool_use, run the requested tools, append the results, call again.docs · L1
ToolA capability you describe to the model with a name, description and input_schema. Client tools run in your code; server tools run on Anthropic's servers.docs · L1
tool_use / tool_resultThe model's request to run a tool (has an id, name, input), and your reply with the output (echoes the id as tool_use_id, sent in a user message).docs · L1
stop_reasonWhy the model stopped: tool_use (run tools, continue), end_turn (done), max_tokens (hit the cap), stop_sequence, refusal.docs · L1
System promptStanding instructions sent with every request, outside the conversation. Where role, rules, org prompt and metadata go.docs · L1
