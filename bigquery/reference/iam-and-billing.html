Rules

  • Hierarchy: organization → folders → project → dataset → table/view. Grants flow down and only add (union). A dataset can't take back a project grant.
  • Job project ≠ data project. Query billed to the job's project; storage to the data's project. Job ID project:region.job_id names who paid.
  • Service accounts: one per purpose, least privilege on the narrowest resource, no keys if avoidable. Who can impersonate it has its access.
  • bigquery.jobs.listAll = every user's job details, including the SQL.

"Who can read hr past the views?"

SELECT object_name, privilege_type, grantee                    -- role + member, one row per grant
FROM `acme-dw`.`region-us`.INFORMATION_SCHEMA.OBJECT_PRIVILEGES -- region qualifier required
WHERE object_name = 'hr';                                       -- dataset: object_name only
-- table: WHERE object_schema = 'hr' AND object_name = 'employee_snapshot'

Shows only grants set on that object. Add: the project's IAM page (Admin, Data Viewer/Editor/Owner, basic roles), folder/org grants, Token Creators on any service account that reads hr, and holders of jobs.listAll.

Grant on a dataset or table with SQL

GRANT `roles/bigquery.dataViewer`                     -- the role
ON SCHEMA `acme-dw`.hr_views                           -- SCHEMA = dataset; also TABLE, VIEW, PROJECT
TO "group:all-employees@acme.com";                     -- user: group: serviceAccount: domain:
