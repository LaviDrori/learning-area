Row Security

Who sees which rows. Sources: Row-level security intro · Use row-level security · Best practices · Authorized views.

What a person sees

  1. No read access to the table → Access Denied. A policy never grants access.
  2. Table has no policies → every row.
  3. Policies exist, none grants them → zero rows, no error.
  4. One or more grant them → the union of those policies' filters.

Two-policy setup

CREATE ROW ACCESS POLICY full_access                      -- create this one first
ON `acme-dw.forecast.predictions`                         -- one table per policy
GRANT TO ('group:data-eng@acme.com',                      -- user: group: serviceAccount: domain:
          'serviceAccount:forecast-app@forecast-app-prod.iam.gserviceaccount.com')
FILTER USING (TRUE);                                      -- all rows: maintainers, writers

CREATE ROW ACCESS POLICY own_stores
ON `acme-dw.forecast.predictions`
GRANT TO ('group:store-managers@acme.com')
FILTER USING (store_id IN (                               -- like a WHERE clause
  SELECT store_id FROM `acme-dw.security.store_access`    -- grantees need read on it; ≤100 MB result
  WHERE email = SESSION_USER()));                         -- email of whoever runs the query

DROP ROW ACCESS POLICY own_stores ON `acme-dw.forecast.predictions`;   -- not the last one
DROP ALL ROW ACCESS POLICIES ON `acme-dw.forecast.predictions`;        -- needed for the last one

List: console View row access policies, or bq ls --row_access_policies project:dataset.table. Members change only via DDL.

Side effects

  • Policy filters don't prune partitions or clusters. Avoid filtering on partitioning/clustering columns; send your own filter too.
  • Bytes stats are hidden: dry run = 0 bytes, total_bytes_billed empty in INFORMATION_SCHEMA.JOBS.
  • Not with: legacy SQL, wildcard tables, table preview, JSON columns. BI Engine and materialized views don't accelerate.
  • Filtered users get no write access. Don't grant bigquery.filteredDataViewer via IAM: policies grant it.
  • Use within your organization. Side channels (query duration) exist.
