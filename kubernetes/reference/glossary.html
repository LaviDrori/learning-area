Glossary

The course's single source of truth for terms. Lessons use these words exactly as defined here. Definitions are quoted or adapted from kubernetes.io.

Core ideas

TermMeaningFrom
ContainerPackaging of an app plus its runtime dependencies, so it runs the same anywhere.docs · L1
Container imageReady-to-run package: code, runtime, libraries, default settings. A container is a running instance of an image.docs · L1
Desired stateWhat you want the cluster to look like. Stored in an object's spec.docs · L1
Current stateWhat the cluster actually looks like right now. Reported in an object's status.docs · L1
Control loop / reconciliationA never-ending loop: observe current state → compare with desired → act to close the gap. Like a thermostat.docs · L1
ControllerA control loop for one kind of object (e.g. ReplicaSet controller keeps N pods alive). It acts by asking the API server, not by running containers itself.docs · L1
PodThe smallest deployable unit: one or more containers that share network and storage. Disposable. You rarely create them directly.docs · L1
ClusterA control plane plus a set of worker nodes.docs · L1
NodeA worker machine (VM or physical) that runs pods.docs · L1

Manifests & workloads

TermMeaningFrom
ObjectA record of intent stored in the API (a Deployment, a Pod, …). Has spec (you write) and status (the system writes).docs · L2
ManifestA YAML/JSON file describing an object. Required fields: apiVersion, kind, metadata, spec.docs · L2
kubectl applySends a manifest to the API server: "make this the desired state".L2
DeploymentWorkload object for stateless apps. Owns ReplicaSets; handles scaling, rollouts and rollbacks.docs · L2
ReplicaSetKeeps N identical pods running. Named [DEPLOYMENT-NAME]-[HASH]. Don't manage one owned by a Deployment directly.docs · L2
Pod templatespec.template: the blueprint for every pod. Changing it (and only it) triggers a rollout.docs · L2
pod-template-hashLabel added by the Deployment controller: a hash of the pod template. Same template, same hash. Never edit it.docs · L2
RolloutReplacing pods with ones from a new template: a new ReplicaSet scales up while the old one scales to 0.docs · L2
LabelKey/value pair attached to an object, e.g. app: nginx. Not unique; many objects share labels.docs · L2
Label selectorA query over labels that picks a set of objects. "The core grouping primitive." A Deployment's selector must match its template labels and is immutable.docs · L2

Build & delivery

TermMeaningFrom
Container registryServer that stores and serves images (ghcr.io, Docker Hub, cloud registries, a customer's private one). Sits between build and run.docs · L3
Image tagHuman-readable version label after :, e.g. v1.4.1. Can be moved to a different image.docs · L3
Image digest@sha256:…, a hash of the image's content. Immutable.docs · L3
imagePullPolicyWhen the kubelet pulls: IfNotPresent (default for real tags and digests) or Always (default for :latest or no tag).docs · L3
imagePullSecretsPod-spec field naming a Secret with credentials for a private registry.docs · L3
ImagePullBackOffContainer can't start because its image can't be pulled (wrong name/tag, missing pull secret, unreachable registry). Retries with growing delay.docs · L3
CIContinuous integration: an automated pipeline (e.g. GitHub Actions) that builds, tests and pushes images on each push/tag.L3
App repo vs config repoApp repo = code + Dockerfile (yours). Config repo = manifests for deploying (often the customer's).L3
GitOpsDesired state lives in a Git repo; an in-cluster tool continuously syncs the cluster to it. A control loop with Git as the thermostat setting.Argo CD · L3
Argo CD / OutOfSync"A declarative, GitOps continuous delivery tool for Kubernetes." OutOfSync = live state deviates from Git.Argo CD · L3
DockerfileThe recipe docker build turns into an image. Each instruction (FROM, RUN, COPY, USER, CMD…) is one step.docs · L4
Base imageThe image named in FROM that yours is built on (e.g. python:3.12-slim). You inherit its OS, its tools and its default user.docs · L4
Exec form vs shell formCMD ["app", "arg"] runs the app directly as PID 1. CMD app arg runs it under /bin/sh -c, which doesn't pass signals on.docs · L4
PID 1The container's main process. It's the one that receives the kubelet's stop signal.docs · L4
SIGTERM / SIGKILLSIGTERM = "please stop" (catchable: finish work, then exit). SIGKILL = immediate kill, can't be caught. The kubelet sends SIGTERM first, then SIGKILL after the grace period.docs · L4
terminationGracePeriodSecondsPod-spec field: the maximum wait between SIGTERM and SIGKILL. Default 30.docs · L4
runAsNonRootsecurityContext field. If true, the kubelet refuses to start a container that would run as UID 0, or whose image user is a non-numeric name it can't verify.docs · L4
Pod Security StandardsThree built-in policy levels: Privileged, Baseline, Restricted. Restricted ("current Pod hardening best practices") requires non-root.docs · L4
.dockerignoreFile listing paths COPY must skip (.git, .venv, .env…).docs · L4

Networking

TermMeaningFrom
Service"An abstraction to help you expose groups of Pods over a network": a stable name, a stable virtual IP and a label selector in front of ever-changing pods.docs · L5
Cluster IPThe virtual IP a Service gets at creation and keeps. Only routable inside the cluster.docs · L5
EndpointSliceThe live list of pod IP:port pairs behind a Service, kept up to date by a controller. ENDPOINTS <none> = the selector matches no pods.docs · L5
port / targetPortport = what clients dial on the Service. targetPort = where the Service sends traffic on each pod; defaults to port. targetPort must equal the app's real listen port.docs · L5
containerPortPod-spec documentation of a port the container listens on. Omitting it doesn't block the port. Can carry a name for a named targetPort.docs · L2, L5
Service typeClusterIP (default, in-cluster only), NodePort (every node's IP, port 30000-32767), LoadBalancer (external load balancer), ExternalName (DNS alias).docs · L5
IngressObject that routes HTTP(S) from outside by hostname/path to Services and can terminate TLS. Needs an Ingress controller. API frozen.docs · L5
Gateway APIThe recommended successor to Ingress. A Gateway is the entry point; an HTTPRoute maps hostnames/paths to Services.docs · L5
Service DNS namesvc from the same namespace, svc.namespace from another, svc.namespace.svc.cluster.local fully qualified.docs · L5
0.0.0.0 vs 127.0.0.1Listen address. 0.0.0.0 = all interfaces, reachable from other pods. 127.0.0.1 = localhost, reachable only inside the same pod.uvicorn · L5
kubectl port-forwardTunnel from a laptop port into a pod or Service: service/web 5000:8080 = local 5000 → Service port 8080.docs · L5

Control plane, the brain

ComponentJob, in one line
kube-apiserverThe front door. Every read/write (yours, and every component's) goes through its HTTP API.
etcdConsistent, highly-available key-value store holding all cluster data, desired state included.
kube-schedulerFinds pods with no node yet and picks a suitable node for each.
kube-controller-managerRuns the built-in controllers (ReplicaSet, Node, Job, …).
cloud-controller-managerOptional. Talks to the cloud provider (load balancers, node VMs).

Node components, the hands

ComponentJob, in one line
kubeletAgent on every node. Makes sure the pods assigned to its node are running and restarts crashed containers.
Container runtimeSoftware that actually runs containers (e.g. containerd).
kube-proxyOptional. Maintains network rules on the node that implement Services.

Three failures, three different healers

What brokeWho fixes itPod name changes?
Container crasheskubelet restarts it in placeNo, restart count goes up
Pod deletedReplicaSet controller creates a replacementYes
Node diesNode controller evicts, ReplicaSet replaces, scheduler places it elsewhereYes
API server downNobody can act until it's back. Running pods keep running; nothing new happens. HA clusters run 3+ API servers behind a load balancer.n/a
