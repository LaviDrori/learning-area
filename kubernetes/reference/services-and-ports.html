Services and Ports

How traffic reaches your container. Sources: Service · DNS · Ingress · Debug Services.

Template

apiVersion: v1                 # core API group: plain v1
kind: Service
metadata:
  name: forecast-api           # also the DNS name: http://forecast-api
spec:
  type: ClusterIP              # default: in-cluster only; Ingress/Gateway in front
  selector:
    app: forecast-api          # must equal the pod template labels (no matchLabels here)
  ports:
  - name: http                 # required once there are 2+ ports
    protocol: TCP              # default; HTTP runs over TCP
    port: 80                   # what clients dial (customer's choice)
    targetPort: 8000           # where your app REALLY listens; defaults to port if omitted

Service types

TypeReachable from
ClusterIP (default)inside the cluster only
NodePortevery node's IP at a port from 30000-32767; includes a ClusterIP
LoadBalanceran external load balancer, usually from the cloud provider
Ingress / Gatewaynot a type: HTTP(S) routing by host and path to ClusterIP Services, TLS termination. Ingress is frozen; Gateway is recommended

Cluster DNS names

forecast-api                                # from the same namespace
forecast-api.prod                           # from another namespace: service.namespace
forecast-api.prod.svc.cluster.local         # fully qualified (cluster.local is the usual domain)

Your answer to "what port, how do we expose it?"

"HTTP on port 8000, bound to 0.0.0.0. Point a ClusterIP Service's targetPort at 8000 and route to it from your Ingress or Gateway. TLS terminates there."

Debug commands

kubectl get service forecast-api -o yaml                              # check selector, port, targetPort
kubectl get endpointslices -l kubernetes.io/service-name=forecast-api # which pod IPs are behind it
kubectl get pods -l app=forecast-api --show-labels                    # run the selector yourself; see real labels
kubectl port-forward service/forecast-api 5000:80                     # laptop:5000 → Service port 80 → targetPort
