Jenkins Glossary & Cheat Sheet

Terms as the official docs define them. Sources: Glossary · Pipeline Syntax · Multibranch.

PR to ✓, in six hops

  1. You push / open a PR (code + Jenkinsfile)
  2. Git host sends a webhook to the controller (/github-webhook/ for GitHub)
  3. Multibranch Pipeline matches the branch/PR and starts a build
  4. Build waits in the queue for a free executor on an agent with the right label
  5. Agent checks out into a workspace and runs the stages/steps
  6. Controller reports a commit status (✓/✗) back to the PR

Terms

TermMeaning
ControllerThe central process: stores configuration, loads plugins, serves the UI. Holds the queue, history, credentials. Shouldn't run builds itself.
AgentA machine or container that connects to the controller and runs the actual work
NodeAny machine capable of executing pipelines or jobs
ExecutorA slot for running one piece of work on a node. 2 executors = 2 concurrent builds.
LabelText grouping agents by capability (python, docker); pipelines request a label
QueueBuilds waiting for a free matching executor
Job / ItemA configured description of work. "Project" is a deprecated synonym.
BuildThe result of a single execution of a job (build #57)
PipelineA user-defined model of a CD pipeline, usually written in a Jenkinsfile
JenkinsfileThe text file in your repo that defines the pipeline ("pipeline-as-code")
Declarative / ScriptedThe two Jenkinsfile syntaxes. Declarative (pipeline { … }) is the more readable one.
StageA conceptually distinct part of the pipeline (Lint, Test, Deploy), shown as a box in the UI
StepA single task, e.g. sh 'pytest'
WorkspaceA disposable directory on a node where a build works
ArtifactAn immutable file produced by a build and archived on the controller
Multibranch PipelineOne job per repo, which auto-creates a pipeline per branch/PR containing a Jenkinsfile
Scan / re-indexMultibranch looking at the repo again to discover new or removed branches and PRs
Organization FolderWatches a whole GitHub/Bitbucket/GitLab org and creates multibranch jobs per repo
WebhookHTTP message from the Git host telling Jenkins something happened
Commit statusThe ✓/✗ Jenkins reports back on a commit/PR
CredentialA secret stored encrypted on the controller and referenced by ID
PluginAn extension to Jenkins core (Git, GitHub, credentials… nearly everything is a plugin)
Upstream / DownstreamA job that triggers another / the job that gets triggered
Console outputThe full log of a build

Declarative Jenkinsfile anatomy

pipeline {
  agent { label 'python' }            // where it runs
  triggers { cron('H 2 * * *') }      // optional schedule; H = stable per-job minute
  parameters { string(name: 'ENV', defaultValue: 'staging') }  // asked on manual run → params.ENV
  environment { TOKEN = credentials('my-id') }  // secret by ID
  stages {
    stage('Test')   { steps { sh 'pytest' } }
    stage('Deploy') {
      when { branch 'main' }          // multibranch only; also: changeRequest()
      input { message 'Deploy?' }     // pause for human approval
      steps { sh './deploy.sh' }
    }
  }
  post { always { … }  success { … }  failure { … }  unstable { … }  changed { … } }
}
